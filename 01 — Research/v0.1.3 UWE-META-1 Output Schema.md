# v0.1.3 UWE-META/1 Output Schema

## 1. Status and scope

This document defines the wire-level contract for the v0.1.3 read-only metadata probe. It is normative for record framing, field order, escaping, null representation, status values, budgets and parser behavior. It does not authorize implementation, compilation, packaging, installation or game execution.

The protocol contains metadata only. It MUST NOT contain arbitrary runtime field values, object dumps, player/world/save data, exception messages, stack traces, file paths unrelated to the probe, or secrets.

## 2. Encoding and framing

- Encoding: UTF-8 without BOM.
- One record per physical line; line terminator is LF (U+000A). A final LF after SUMMARY is recommended.
- Field separator: vertical bar `|` (U+007C).
- Every record begins with the literal `UWE-META/1`, followed by a record-kind token.
- Tokens are case-sensitive ASCII. Enum/status tokens are uppercase.
- Empty fields are forbidden. Use `-` for a value that is structurally absent/not applicable and `UNKNOWN` when the value exists but could not safely be obtained.
- Literal text equal to `-` or `UNKNOWN` MUST be escaped by prefixing its first character with a backslash (thus `\-` or `\UNKNOWN`), so sentinels remain unambiguous.
- Numeric values use invariant culture, decimal digits, no grouping separators. Booleans are `TRUE` or `FALSE`.
- IDs are run-local opaque tokens: `R1` for the single run; assembly/type/member IDs use monotonically assigned record IDs in deterministic output order (for example `A0001`, `T0001`, `M0001`). IDs are references, not identities across runs.
- Text fields are Unicode. Preserve original metadata spelling; do not normalize case or Unicode. Sorting uses ordinal comparison of the specified identity keys.

### 2.1 Escaping

Escape each field independently, after converting it to its protocol string:

| Input character | Encoded form |
|---|---|
| backslash `\\` | `\\\\` |
| pipe `|` | `\\|` |
| tab U+0009 | `\\t` |
| carriage return U+000D | `\\r` |
| line feed U+000A | `\\n` |

Backslash MUST be escaped first. The decoder processes left-to-right and recognizes only `\\\\`, `\\|`, `\\t`, `\\r`, `\\n`, `\\-` and `\\U` for sentinel-literal disambiguation; unknown escape sequences are malformed records. No raw tab, CR or LF is permitted inside a record.

The 2,048-character single-record and 48,000-character global ceilings are enforced independently on both the unescaped logical payload and the final escaped serialized payload, using .NET string Length semantics (UTF-16 code units). Include the protocol prefix and field separators in both measurements; exclude physical LF terminators. If either ceiling would be exceeded, stop adding ordinary records, emit a bounded TRUNCATED record if reserved capacity permits, and finish with PARTIAL; if SUMMARY cannot be emitted, the run is FAILED.

## 3. Record grammar

The grammar is positional. The first two fields are always `UWE-META/1|KIND`. The schemas below list all remaining fields in order. Parsers MUST reject records with too few or too many fields for the declared version/kind; forward-compatible additions require a new protocol version or an explicitly versioned extension record.

Common conventions:
- `id`: run-local record ID.
- `parent_id`: ID of the owning record, or `-`.
- `identity`: stable metadata identity string, never an object hash/address.
- `status`: one of the enumerated tokens for that record kind.
- Any field marked nullable uses `-` or `UNKNOWN`, never an empty field.

### 3.1 RUN

`UWE-META/1|RUN|run_id|probe_version|protocol_version|started_utc|game_version|game_build|rml_version|unity_version|framework_target|runtime_version|status`

- `probe_version`: source-defined semantic version.
- `protocol_version`: literal `1`.
- `started_utc`: ISO-8601 UTC timestamp with `Z`, or UNKNOWN. Do not infer it from local timezone.
- Version/evidence fields are UNKNOWN unless actually supplied by a trusted source in the running process.
- Initial RUN status is RUNNING. A final RUN record is not emitted; terminal state belongs to SUMMARY.

### 3.2 ASSEMBLY

`UWE-META/1|ASSEMBLY|assembly_id|run_id|full_identity|simple_name|module_name|module_mvid|inspection_status|type_count|candidate_count|error_count`

`inspection_status`: COMPLETE, PARTIAL, FAILED, SKIPPED, or UNKNOWN. Counts are non-negative decimal integers or UNKNOWN. Assembly identity and module fields use null-safe formatting.

### 3.3 TYPE

`UWE-META/1|TYPE|type_id|assembly_id|full_name|short_name|declaring_type|base_type|visibility|kind|is_abstract|is_sealed|is_interface|is_enum|is_value_type|resolution_status`

- `visibility`: PUBLIC, NESTED_PUBLIC, NESTED_FAMILY, NESTED_ASSEMBLY, NESTED_PRIVATE, NESTED_FAMILY_OR_ASSEMBLY, NESTED_FAMILY_AND_ASSEMBLY, NON_PUBLIC, UNKNOWN.
- `kind`: CLASS, STRUCT, INTERFACE, ENUM, DELEGATE, GENERIC_PARAMETER, OTHER, UNKNOWN.
- `resolution_status`: CANDIDATE, RESOLVED, AMBIGUOUS, NOT_FOUND, TRUNCATED, UNKNOWN.
- Boolean flags use TRUE/FALSE/UNKNOWN.

### 3.4 FIELD

`UWE-META/1|FIELD|member_id|type_id|name|declaring_type|field_type|visibility|scope|is_readonly|is_literal`

`scope`: STATIC, INSTANCE, UNKNOWN. Do not include enum literal constant fields; enum names/values belong to ENUM.

### 3.5 PROPERTY

`UWE-META/1|PROPERTY|member_id|type_id|name|declaring_type|property_type|index_parameters|getter_signature|setter_signature`

Each signature is either `-`, UNKNOWN, or a compact metadata signature with accessor visibility and static/instance scope. Signatures are descriptive text and MUST use the common escaping rules. Accessors are never invoked and do not appear again as METHOD records.

### 3.6 EVENT

`UWE-META/1|EVENT|member_id|type_id|name|declaring_type|handler_type|add_signature|remove_signature|raise_signature`

Accessor signatures follow PROPERTY rules. Accessors are never invoked and do not appear again as METHOD records.

### 3.7 METHOD

`UWE-META/1|METHOD|member_id|type_id|name|declaring_type|return_type|visibility|scope|is_abstract|is_virtual|is_final|generic_arity|parameters`

Parameters use a compact ordered signature representation: `position:name:type:flags`, comma-separated inside the field. Names may be `-`; flags are a comma-separated subset of IN, OUT, OPTIONAL, PARAMS, REF, OUT_BYREF. The complete parameter field is escaped as one field. More than 16 parameters is represented by the first 16 plus a literal truncation marker and a TRUNCATED record. Property/event accessors MUST be excluded.

### 3.8 CTOR

`UWE-META/1|CTOR|member_id|type_id|declaring_type|visibility|scope|parameters`

Static constructors may be described as metadata only; MUST NOT be executed. Parameter format and ceiling match METHOD.

### 3.9 ENUM

`UWE-META/1|ENUM|type_id|underlying_type|constant_count|constants`

`constants` is a deterministic comma-separated sequence of `name=raw_constant` pairs, capped at 64. Raw values are invariant decimal strings for supported integral underlying types; names and values are escaped as part of the field. If a value cannot be read safely from literal metadata, use UNKNOWN for that value and mark PARTIAL. Do not use Enum.GetValues or infer values from order. If more than 64 constants exist, emit TRUNCATED and PARTIAL.

### 3.10 ERROR

`UWE-META/1|ERROR|error_id|run_id|scope|parent_id|operation|exception_type|sequence|recoverable`

- `scope`: RUN, ASSEMBLY, TYPE, MEMBER, OUTPUT.
- `operation`: bounded static operation token, not a raw exception message.
- `exception_type`: exception type full name or UNKNOWN.
- `sequence`: monotonically increasing run-local integer assigned after deterministic sorting of retained ERROR descriptors; it is not encounter order and is not a sort key.
- `recoverable`: TRUE/FALSE.
- Never include exception.Message, stack trace, arbitrary exception.Data, or ToString() output.

### 3.11 TRUNCATED

`UWE-META/1|TRUNCATED|run_id|scope|parent_id|budget_name|limit|observed|total|reason`

- `scope`: RUN, ASSEMBLY, TARGET, TYPE, MEMBER, OUTPUT.
- `limit` and `observed` are integers or UNKNOWN.
- `total` is integer or UNKNOWN.
- `reason` is a bounded static token such as LIMIT_REACHED, OUTPUT_BUDGET, ENUMERATION_INCOMPLETE, IDENTITY_UNAVAILABLE.

### 3.12 SUMMARY

`UWE-META/1|SUMMARY|run_id|terminal_status|assemblies_seen|assemblies_inspected|targets_required|targets_resolved|targets_missing|targets_ambiguous|types_emitted|members_emitted|errors_emitted|errors_overflow|truncations|records_emitted|characters_emitted|ordering_uncertain|output_complete`

- `terminal_status`: COMPLETE, PARTIAL, FAILED.
- Counts are non-negative integers or UNKNOWN.
- `errors_overflow`, `ordering_uncertain`, `output_complete`: TRUE/FALSE.
- SUMMARY MUST be the final record. No record may follow it.
- `characters_emitted` is the final escaped serialized payload length of every committed record, including the SUMMARY record itself and any terminal TRUNCATED record; physical LF terminators are excluded. The writer must solve the bounded fixed-point equation after all preceding records are fixed; the parser independently recomputes and verifies the value.
- Logical unescaped and escaped serialized global character totals are checked independently. SUMMARY consists only of fixed ASCII tokens and numeric fields, so its own logical and escaped lengths are equal.
- A parser MUST treat a stream without exactly one final SUMMARY as incomplete/FAILED, regardless of earlier RUN state or apparent success.

## 4. Deterministic ordering

Emit records in this order:
1. RUN;
2. ASSEMBLY records sorted by assembly identity, module name, MVID;
3. TYPE candidate records sorted by assembly identity, module identity, FullName, declaring type, metadata token;
4. target inventory records in target allowlist order;
5. within each target: FIELD, PROPERTY, EVENT, METHOD, CTOR, ENUM; within category sort by ordinal metadata identity;
6. ERROR/TRUNCATED records grouped after all inventory. Sort ERROR records by scope, stable parent metadata identity, operation, exception type and recoverable flag; sort TRUNCATED records by deterministic scope, stable parent identity, operation/budget and reason. Assign ERROR.sequence only after this ordering. For otherwise identical diagnostics, preserve multiplicity and assign consecutive sequence values in the sorted output group;
7. SUMMARY last.

If a sort key is unavailable, use a stable explicit UNKNOWN marker and mark ordering_uncertain=TRUE/PARTIAL. Never use object hash codes, runtime addresses, current culture, reflection enumeration order or thread scheduling as tie-breakers. A run-local ID is assigned only after deterministic ordering is established.

## 5. Status derivation

- COMPLETE only if all nine required targets resolve uniquely, all required queries finish, no cap/truncation/ambiguity/missing target/recoverable error/ordering uncertainty/output failure occurs, and SUMMARY is emitted.
- PARTIAL for any missing/ambiguous target, skipped or partially inspected assembly, reflection exception, null type slot, recoverable error, truncation, unknown identity affecting resolution/order, or output omission.
- FAILED if safe enumeration cannot begin/continue at run level, an internal invariant fails, writer/logger fails such that truthful output cannot be completed, or terminal SUMMARY cannot be emitted.
- An empty but successfully queried category is valid and does not itself cause PARTIAL.
- Error-record overflow does not permit errors to be silently ignored: set errors_overflow=TRUE, emit a TRUNCATED record if possible, and ensure status is at least PARTIAL.
- If an earlier condition would be PARTIAL but SUMMARY cannot be emitted, FAILED takes precedence.

## 6. Parser requirements

A conforming parser MUST:
- validate UTF-8, version, record kind, exact field count, escape sequences and token domains;
- reject malformed records without shifting subsequent field boundaries;
- preserve UNKNOWN versus '-' distinctions;
- verify IDs are unique within a run and all referenced parent IDs exist or are explicitly UNKNOWN;
- verify SUMMARY is unique and final;
- recompute record/character counts and flag mismatches;
- never interpret text fields as executable code, paths to open, reflection instructions or commands;
- tolerate unknown future protocol versions by reporting unsupported version, not by guessing field positions.

## 7. Budget mapping

The output protocol inherits the implementation plan ceilings: 128 assemblies, 8 retained candidate identities per target, 64 shared members per resolved type, 16 parameters per signature, 64 enum constants per enum, recursion depth 8, generic arguments 16, 32 ERROR records, 512 total records including SUMMARY, 48,000 UTF-16 code units globally and 2,048 UTF-16 code units per record, each enforced independently on both unescaped logical and final escaped serialized payloads; zero retries.

All budgets are global or scoped exactly as stated in the implementation plan. Every serialized record kind consumes the 512-record global ceiling, including RUN, ERROR, TRUNCATED and SUMMARY; the 32-ERROR ceiling is an additional cap. Reserve capacity for exactly one final SUMMARY and for any mandatory terminal diagnostic/truncation record. The writer and parser MUST independently enforce both unescaped logical and final escaped serialized UTF-16 character ceilings. Reflection APIs may allocate full arrays before caller-side caps; no hard allocation/time guarantee is implied.

## 8. Compatibility and security constraints

- Implementation must remain C# 7.3 and .NET Framework 4.8 reference-surface compatible.
- No new NuGet dependencies or project format changes.
- Do not load assemblies, instantiate types, execute static constructors, invoke methods/accessors, inspect live Unity objects, load bundles/scenes, or mutate game/save/network state.
- Use only already-loaded assemblies and metadata APIs.
- The schema is not a remote command protocol; no record can request an action.

## 10. G0.2 decisions — resolved in the design

The following choices are normative for UWE-META/1 and supersede tentative wording in earlier sections.

1. **BOM: forbidden.** Writers emit UTF-8 without BOM. Parsers reject a leading UTF-8 BOM as a framing violation; they do not silently strip it.
2. **IDs: deterministic within one stream, not persistent across runs.** The probe performs one scan per output stream. It sorts records using section 4, then assigns sequential IDs. IDs are unique and stable for identical metadata inventories and identical scan options. They are not cross-build identifiers; stable metadata identity fields remain the comparison keys. RUN uses the fixed stream-local token R1.
3. **Character limits: both pre-escape and serialized limits apply.** The 2,048 UTF-16-code-unit per-record and 48,000 global ceilings are hard limits on the final escaped serialized payload, excluding LF terminators. The writer MUST additionally ensure the unescaped logical record is no longer than 2,048 UTF-16 code units and the unescaped logical stream no longer than 48,000 code units. The earlier phrase “before escaping” describes this additional logical-content guard, not permission to exceed the serialized ceiling. Separators count in both measurements; LF terminators do not. If escaping causes a ceiling to be reached, the writer stops adding ordinary records, emits a bounded TRUNCATED record if reserved capacity permits, then SUMMARY. If SUMMARY cannot fit, FAILED.
4. **ERROR/TRUNCATED placement: grouped after inventory.** Emit normal inventory records in deterministic order first, followed by diagnostic records sorted by deterministic scope/parent/operation/code keys. Do not emit inline diagnostics interleaved with reflection enumeration. Error encounter sequence is diagnostic metadata only and MUST NOT be used as an unstable ordering key; where otherwise identical diagnostics occur, use a deterministic occurrence ordinal within the same sorted group.
5. **Timestamp/version provenance: trusted values only.** started_utc and game/RML/Unity/runtime version fields are UNKNOWN unless read from a documented, non-mutating and trustworthy runtime source. Never infer values from assembly names, local machine configuration, repository history or current wall clock. A timestamp is excluded from deterministic-fixture comparisons only when the trusted source genuinely supplies it; otherwise it remains UNKNOWN.

### 10.1 Normative ordering and identity notes

- Assembly identity sorting uses the exact reflection identity string, then module name, then MVID in ordinal order; missing sort components cause ordering_uncertain=TRUE and PARTIAL rather than fallback to discovery order.
- Type/member metadata token is a tie-breaker only when available and valid for the inspected module. If unavailable, the stable identity tuple must still uniquely order the item; otherwise mark PARTIAL and do not resolve an affected target.
- Run-local record IDs are assigned only after the full bounded record inventory and diagnostic set have been sorted. IDs are references only; comparisons across runs use assembly/type/member identity fields.
- Diagnostics use stable error codes/operation tokens and exception type names only. They never serialize localized exception messages or raw stack traces.
- SUMMARY counters count records actually serialized, including RUN and SUMMARY. characters_emitted counts serialized payload UTF-16 code units including field separators and excluding LF terminators. The parser independently recomputes this value.

## 10.2 G0.3.1 review corrections — 2026-11-09

The `SUMMARY.characters_emitted` field is self-referential because it counts the serialized SUMMARY record that contains it. The writer MUST compute a fixed point from the committed pre-SUMMARY payload and the SUMMARY length for the candidate decimal value, repeating until the value is stable. The value is the escaped serialized payload count; the parser independently recomputes it. The final logical and escaped totals are still checked separately.

The ERROR writer MUST retain a deterministic top-32 set by stable diagnostic identity rather than the first 32 encountered. ERROR.sequence is assigned after sorting the retained set and is not an encounter-order value. Unknown sort identity marks the run PARTIAL; it never authorizes a discovery-order fallback.

Acceptance coverage: OS16–OS17. These are design requirements only; no writer, parser or fixture test has been executed. G0 remains REVIEWED — APPROVAL PENDING.
