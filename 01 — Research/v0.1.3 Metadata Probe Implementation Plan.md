# v0.1.3 Metadata Probe Implementation Plan

## Purpose

v0.1.3 is a proposed read-only metadata diagnostic. It is not a custom Landmark prototype and must not change the world. This document is design-only: no C# source has been changed, compiled, packaged, installed, or executed for v0.1.3.

## Hard safety boundary

The probe may inspect type and member metadata only. It must not instantiate game types or Unity objects; invoke constructors, methods, property getters, or event accessors; load/unload AssetBundles; create, spawn, register, or remove ChunkPoints or Landmarks; write saves; send network messages; or apply Harmony patches.

Metadata cannot prove manager ownership, call order, registration semantics, persistence, or network authority. Those require exact target-build IL/call-site evidence.

## Target type allowlist

| Type | Reason |
|---|---|
| Landmark | Landmark lifecycle and identity contract |
| LandmarkData | Landmark definition/metadata shape |
| AsyncedLandmark | Hooker collection element |
| SceneLoader | Scene and Landmark coordination |
| AssetBundleManager | Bundle lifecycle surface |
| AssetBundleHooker | Bundle-keyed registration surface |
| ChunkManager | Vanilla placement coordinator |
| ChunkPoint | Placement record |
| ChunkPointType | Vanilla enum surface |

Discover all candidates; never silently select the first match by short type name.

## Discovery requirements

1. Enumerate currently loaded assemblies in stable order by full assembly identity. Do not load extra assemblies.
2. Record assembly full name, module name, full type name, base type, declaring type for nested types, and visibility.
3. Record every candidate for each target name. Report duplicate short names explicitly.
4. Emit explicit NOT_FOUND for missing types.
5. Isolate failures at assembly, type, and member boundaries; continue where safe.
6. Do not use object enumeration or instantiate types to discover metadata.

## Member inventory

For each resolved type, inspect metadata for:
- constructors (signature only);
- declared fields;
- declared properties and accessor signatures;
- declared events and accessor signatures;
- declared methods and every overload;
- enum underlying type and named constants;
- base type and declaring assembly.

For methods and accessors, record full declaring type, name, visibility, static/instance, abstract/virtual/final flags, generic arity, return type, ordered parameter types and parameter attributes.

For fields, record field type, visibility, static/instance, readonly/literal flags, and declaring type.

Use unambiguous recursive type formatting for arrays, pointers, by-reference types, generic definitions/arguments, nested types, and generic parameters. If formatting fails, emit a stable fallback and warning rather than aborting the scan.

No property getter, constructor, event accessor, or game method may be invoked.

## Output, determinism, and limits

- Sort assemblies, candidates, and members ordinally by stable identity.
- Configure hard limits for assemblies, duplicate candidates, members per type, and total output lines.
- Log configured limits, actual counts, and explicit truncation markers.
- If omitted counts cannot be computed safely, say UNKNOWN; never imply a truncated scan is complete.
- Do not dump arbitrary runtime object values, player data, world data, or heap contents.
- Use stable record prefixes: TYPE, FIELD, PROPERTY, EVENT, METHOD, ENUM, ERROR, TRUNCATED, SUMMARY.
- Completion status must be COMPLETE, PARTIAL, or FAILED.

Illustrative records:

`TYPE|assembly identity|full type name|base type|status`
`FIELD|declaring type|name|field type|visibility|static/instance|flags`
`PROPERTY|declaring type|name|property type|accessor signatures`
`EVENT|declaring type|name|handler type|accessor signatures`
`METHOD|declaring type|name|return type|parameters|visibility|static/instance|flags`
`SUMMARY|types found|duplicates|members emitted|truncations|errors`

## Exception and retry policy

- Catch failures at assembly, type, and individual-member boundaries.
- Record operation and exception type; avoid noisy arbitrary exception messages.
- Continue after a member-level failure.
- A type-level failure must not stop unrelated types.
- Mark completion only after the summary has been emitted.
- Do not add unbounded automatic retries. Any retry must be bounded and reviewed separately.

## Source safety checklist

Before implementation, confirm:
- all reflection calls are metadata-only;
- no getters, constructors, game methods, or event accessors are invoked;
- no Unity object enumeration/creation is needed;
- no AssetBundle, scene, save, network, or world API is called;
- every loop and output path has a hard bound;
- duplicate names and truncation are visible;
- existing RML entry point/lifecycle integration is unchanged unless separately justified.

## Acceptance tests

| ID | Test | Expected result |
|---|---|---|
| M01 | All target types resolve | Full assembly and type identity recorded |
| M02 | A target type is absent | NOT_FOUND; remaining scan continues |
| M03 | Duplicate short names exist | Every candidate reported; no arbitrary selection |
| M04 | One member query fails | Error recorded; other members/types continue |
| M05 | Member cap is reached | TRUNCATED marker and partial status |
| M06 | Generic/nested/array/by-ref signatures occur | Unambiguous formatting or explicit fallback warning |
| M07 | Properties/events exist | Metadata recorded; accessors not invoked |
| M08 | Same build scanned twice | Stable ordering and equivalent output |
| M09 | Safety source review | No prohibited calls or mutation paths |
| M10 | Log budget is reached | PARTIAL, never false COMPLETE |
| M11 | Assembly enumeration fails | Bounded error record; no crash/retry loop |
| M12 | Disposable-world smoke test | Mod loads; scan completes; world/save unchanged |

M01–M11 are source/fixture-level checks where feasible. M12 requires explicit user authorization for local build and game testing; it is not part of repository-only work.

## Required evidence before coding

Preserve text-only evidence for:
- exact Raft, Steam build, Unity and RML versions;
- assembly names and hashes containing the target types;
- full metadata signatures and duplicate type-name inventory;
- exact project target framework/compiler constraints;
- IL/call-site extracts for manager ownership, registration, identity allocation, persistence, and network authority.

The metadata probe cannot establish the semantic contracts in the final bullet; offline IL analysis is still required.

## Release gates

- G0: design reviewed; schema and limits approved.
- G1: source implementation reviewed against the safety checklist.
- G2: strict compile against exact target references.
- G3: package version and source integrity verified.
- G4: runtime smoke test only after explicit user authorization, in a disposable world.
- G5: text-only evidence attached and API Evidence Matrix updated with build/hash provenance.

Until all applicable gates are met, v0.1.3 remains NOT IMPLEMENTED.

## Decision

This plan is ready for repository review. C# implementation remains deferred while the project is repository-only and the repository lacks the target-build metadata/IL needed to validate exact contracts.
