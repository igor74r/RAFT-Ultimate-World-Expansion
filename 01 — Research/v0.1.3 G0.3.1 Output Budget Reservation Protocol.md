# v0.1.3 G0.3.1 Output Budget Reservation Protocol

## 1. Status and scope

This document proposes a deterministic output-budget reservation algorithm for UWE-META/1. It is design-only and does not authorize implementation, compilation, packaging, installation, or game execution. It supplements the Output Schema and Implementation Plan; it does not change their normative status until explicitly incorporated and reviewed.

## 2. Fixed global ceilings

The algorithm uses the existing ceilings without increasing them:

- 512 serialized records globally, including RUN, ERROR, TRUNCATED and SUMMARY.
- 48,000 UTF-16 code units globally.
- 2,048 UTF-16 code units per record.
- 32 ERROR records globally, as an additional cap.
- Both logical unescaped and final escaped payload lengths are checked independently.
- LF terminators are excluded; protocol prefix and separators are included.

## 3. Terminal reserve

Before ordinary output begins, reserve:

- exactly 2 record slots;
- 4,096 UTF-16 code units in each of the two independently measured character budgets.

The reserve is sufficient for one bounded aggregate terminal TRUNCATED record (at most 2,048 code units) and one SUMMARY record (at most 2,048 code units). The ordinary-output ceilings are therefore 510 records and 43,904 code units in each character budget.

RUN and all inventory records consume ordinary capacity. ERROR records also consume ordinary capacity and remain subject to the additional 32-record ceiling. A reserved slot is never borrowed by ordinary output, even when the run appears likely to complete without truncation.

## 4. Deterministic write algorithm

1. Initialize the writer with the full global ceilings and the terminal reserve above.
2. Validate each candidate record against the per-record logical and escaped limits before writing it.
3. Write ordinary records only while both ordinary record and both ordinary character budgets remain available.
4. Maintain a bounded ordered set of at most 32 ERROR descriptors; do not retain the first 32 by encounter order. The stable key is (scope, stable parent metadata identity, operation, exception type, recoverable). Insert each descriptor into the set and, when it exceeds 32, discard the lexicographically greatest key and set errors_overflow. This produces the same retained top-32 set regardless of discovery order. Identical descriptors retain multiplicity up to the cap. If a key component is UNKNOWN, use that explicit value and mark ordering_uncertain/PARTIAL; never fall back to encounter order, object hash, or runtime address. After inventory is fixed, sort retained descriptors and assign ERROR.sequence as 1..N in serialized order; sequence is not encounter order and is not a sort key.
5. If an ordinary inventory record cannot be emitted because any ordinary budget is exhausted, stop ordinary inventory output. Do not retry, replace, or partially write that record. After inventory, emit retained ERROR and scope-specific TRUNCATED descriptors in deterministic order while ordinary capacity remains; any diagnostic omitted for record, character, or error-cap reasons sets the appropriate overflow/omission state.
6. If any output was omitted, any ERROR overflow occurred, or any budget-triggered truncation occurred, emit exactly one aggregate terminal TRUNCATED record using bounded static tokens. Its scope is RUN or OUTPUT as appropriate; its reason identifies the primary limiting condition. The aggregate record discloses that additional omissions/conditions may have been coalesced; it does not invent an exact omitted count when that count is not safely known.
7. Emit exactly one SUMMARY as the final record. Its counts reflect records actually committed to the output, including the terminal TRUNCATED when present. Set PARTIAL whenever any record, diagnostic, candidate, or inventory item was omitted.
8. If the writer cannot commit the required terminal TRUNCATED or SUMMARY within its reserved limits, or encounters an I/O/logger failure that makes truthful completion impossible, the run is FAILED. Never emit or report COMPLETE without a successfully committed final SUMMARY.

## 5. Truncation and diagnostic semantics

- The terminal reserve is for at most one aggregate TRUNCATED record, not one record per exhausted budget.
- Earlier, scope-specific TRUNCATED records may be emitted as ordinary records while ordinary capacity remains. If they cannot be emitted, their conditions are coalesced into the terminal record.
- ERROR records are emitted in deterministic order from the bounded buffer. If the 32-error cap or ordinary output budget prevents emission of every observed error, set errors_overflow=TRUE and ensure the aggregate terminal TRUNCATED is emitted when possible.
- A diagnostic that cannot be represented without exceeding a per-record ceiling is replaced by a bounded static diagnostic descriptor; raw exception messages and arbitrary text remain forbidden.
- If exact omitted totals cannot be calculated safely, use UNKNOWN. Never present the number emitted as the total discovered.
- A writer failure is not a budget truncation: it is FAILED if a truthful terminal record cannot be committed.

## 6. Accounting invariants

A conforming implementation and parser must verify:

- records_emitted never exceeds 512 and includes RUN, ERROR, TRUNCATED and SUMMARY;
- SUMMARY is counted exactly once and is final;
- when present, aggregate terminal TRUNCATED is counted exactly once;
- ordinary records never consume the reserved two slots or reserved 4,096 code units;
- each record independently satisfies both 2,048-code-unit measurements;
- global logical and escaped payload totals independently remain at or below 48,000;
- ERROR records never exceed 32;
- characters_emitted equals the final escaped serialized payload length of all committed records, including the SUMMARY record itself and any terminal TRUNCATED record; physical LF terminators are excluded. The writer computes this value by a bounded fixed-point calculation after all pre-SUMMARY records are fixed, and the parser independently recomputes it;
- logical unescaped and escaped serialized totals are checked independently against the global ceiling;
- any omitted output, error overflow, or budget exhaustion prevents COMPLETE;
- inability to commit SUMMARY results in FAILED.

## 7. Required regression cases

| ID | Scenario | Expected result |
|---|---|---|
| BR01 | Exactly 510 ordinary records, no truncation | Reserved capacity remains available; SUMMARY commits |
| BR02 | 511th ordinary record requested | Ordinary output stops; terminal TRUNCATED and SUMMARY use reserved slots |
| BR03 | Ordinary logical character budget reaches 43,904 | Ordinary output stops before consuming terminal reserve |
| BR04 | Ordinary escaped character budget reaches 43,904 first | Same behavior; escaped and logical budgets are independent |
| BR05 | 32 errors plus further observed errors | At most 32 ERROR records retained; overflow flagged; aggregate TRUNCATED emitted |
| BR06 | Several truncation causes occur | At most one aggregate terminal TRUNCATED; reasons safely coalesced |
| BR07 | Terminal TRUNCATED or SUMMARY exceeds its bounded format | FAILED; never false COMPLETE |
| BR08 | Logger fails while writing ordinary output | Attempt only the defined bounded terminal path; FAILED if truthful SUMMARY cannot be committed |
| BR09 | Parser recounts all records and characters | Counts include every record kind and exclude LF terminators |
| BR10 | Run completes without omissions | No terminal TRUNCATED required; SUMMARY is still final |
| BR11 | SUMMARY character count crosses a decimal digit boundary, with and without terminal TRUNCATED | Writer converges to a self-consistent fixed point; parser recomputation matches exactly |
| BR12 | More than 32 ERROR descriptors are observed in different discovery orders | Same deterministic top-32 set and serialized sequence; overflow is TRUE and status is at least PARTIAL |

## 8. Review questions before adoption

1. Approve a fixed reserve of two records and 4,096 UTF-16 code units.
2. Approve coalescing all terminal truncation causes into at most one aggregate TRUNCATED record.
3. Confirm that ordinary capacity is 510 records and 43,904 code units per logical/escaped character budget.
4. Confirm that diagnostic buffering is bounded to 32 ERROR descriptors and sorted before emission.
5. Incorporate this algorithm into the Output Schema, Implementation Plan, and Reflection Safety Specification only after explicit G0 review.

## 10. Cross-review details — 2026-11-09

### 10.1 SUMMARY self-accounting

The schema defines `characters_emitted` as the final escaped serialized payload length and counts the SUMMARY record itself. The value therefore cannot be computed before SUMMARY is serialized. Let `P` be the escaped payload length of all committed records before SUMMARY, including terminal TRUNCATED when present, and let `S(n)` be the escaped length of the SUMMARY record when its `characters_emitted` field contains decimal value `n`. Compute:

1. `n0 = P + S(0)`.
2. Re-serialize SUMMARY with `characters_emitted = n0`; calculate `n1 = P + S(n0)`.
3. Repeat until `n(k+1) == nk`; write that stable value.

The global ceiling limits the value to at most 48,000, so the decimal field is at most five digits and the iteration is bounded. The implementation must still enforce the 2,048 per-record limit and both 48,000 logical/escaped global limits on the final output. SUMMARY fields are fixed ASCII tokens and decimal integers, so its logical and escaped record lengths are equal; preceding-record logical and escaped totals may differ. If no stable value is obtained within the documented bounded iteration or any final limit is exceeded, report FAILED rather than a false COMPLETE/PARTIAL summary.

### 10.2 Deterministic ERROR retention and sequence

The writer must not retain the first 32 errors encountered, because reflection enumeration order is not a stable identity. Keep a bounded top-32 ordered set keyed by scope, stable parent metadata identity, operation, exception type and recoverable flag. When a new descriptor would exceed the cap, retain the lexicographically smallest 32 and set `errors_overflow`. Unknown key components force ordering uncertainty/PARTIAL. Identical descriptors retain multiplicity within the cap. Assign the schema's run-local ERROR.sequence only after the retained set is sorted, starting at 1 in serialized order; sequence is not an encounter-order timestamp or sorting key.

After inventory records are fixed, emit retained ERROR and scope-specific TRUNCATED records in deterministic order while ordinary capacity remains. If any diagnostic is omitted, preserve the terminal reserve and emit the single aggregate terminal TRUNCATED record when possible.

These corrections are design-only. BR11–BR12 have not been executed; G0 formal approval remains pending.
