# v0.1.3 G0.3.2 Diagnostic Overflow and Determinism Audit

## 1. Status

This is a documentation-only review of the G0.3.1 Output Budget Reservation Protocol against UWE-META/1 Output Schema and the Metadata Probe Implementation Plan. No implementation or runtime tests were performed. G0 remains REVIEWED — APPROVAL PENDING.

## 2. Findings

### G032-01 — ERROR retention must not depend on encounter order

The proposal says to buffer no more than 32 ERROR descriptors and sort them before emission. A naïve first-32 buffer would make the retained set depend on reflection/enumeration failure order, even if the final emitted set is sorted.

**Required refinement:** maintain a bounded deterministic top-32 set keyed by the complete stable diagnostic ordering tuple (scope, parent identity, operation/error code, exception type, deterministic occurrence ordinal). When a new descriptor arrives, insert it into that bounded ordered set and discard the greatest key if the set exceeds 32. Never use encounter sequence, thread order, hash codes, or object addresses to choose retained diagnostics. If a stable key or deterministic occurrence ordinal cannot be formed, mark ordering_uncertain/PARTIAL and use an explicitly defined bounded UNKNOWN key; do not silently fall back to arrival order.

### G032-02 — ERROR overflow and output-cap omission are distinct

The 32-ERROR ceiling limits retained/emitted ERROR records. The 512-record and character ceilings may independently prevent some retained diagnostics from being serialized.

**Required refinement:** track bounded booleans/counters for (a) observed diagnostics beyond the 32-error retention ceiling and (b) retained ERROR descriptors omitted because ordinary output capacity was exhausted. Set errors_overflow=TRUE if either category occurs. Exact total diagnostic count is emitted only if safely known; otherwise use UNKNOWN. Both conditions force PARTIAL and require the aggregate terminal TRUNCATED record when it can be committed.

### G032-03 — Reserve arithmetic is internally consistent

Two reserved record slots and 4,096 code units per character-accounting domain can hold one TRUNCATED and one SUMMARY, each at the 2,048 per-record ceiling. This is valid only because both records are independently constrained by both logical and escaped per-record ceilings, and the reserve is maintained separately in both global character domains.

**Required refinement:** state explicitly that reserve consumption is charged by each record's actual logical and escaped lengths independently, not by subtracting a single shared 4,096 counter. Unused reserve is never needed to justify exceeding either hard global ceiling.

### G032-04 — Multiple truncation causes need a deterministic representation

The TRUNCATED schema has one reason field. Coalescing several causes into one record is therefore not a list unless the schema changes.

**Required refinement:** define a fixed reason precedence table and emit exactly one primary reason token. Set SUMMARY.truncations to the number of TRUNCATED records actually emitted, not the number of underlying causes. The terminal TRUNCATED record must state a fixed static coalescing token only if that token is added to the UWE-META/1 reason domain through schema review; otherwise use the highest-priority existing reason and document that secondary causes are coalesced. Never concatenate unbounded reason text into the field.

Suggested precedence (highest first): OUTPUT_WRITER_FAILURE (terminal failure path only; no claim of successful SUMMARY), OUTPUT_BUDGET, ERROR_OVERFLOW, ENUMERATION_INCOMPLETE, then the most specific deterministic local limit reason. Writer failure remains FAILED and must not be disguised as ordinary PARTIAL truncation.

### G032-05 — Inventory/diagnostic ordering and capacity need a single emission plan

The schema requires all inventory before ERROR/TRUNCATED diagnostics. The proposal must not serialize ERROR records during discovery and later attempt to reorder them.

**Required refinement:** collect only bounded diagnostic descriptors during scanning; complete bounded inventory collection; sort inventory and the retained diagnostic top-32 set; then serialize in the schema's prescribed order while preserving terminal reserve. If the inventory alone consumes all ordinary capacity, retained ERROR records may be omitted, errors_overflow is TRUE, and the terminal TRUNCATED reports the omission. No late diagnostic may be inserted before already committed inventory.

### G032-06 — SUMMARY counters need exact meanings

The schema's errors_emitted, errors_overflow, truncations, records_emitted, and characters_emitted fields must describe the committed stream, not merely discovered or buffered items.

**Required refinement:**
- errors_emitted is the number of ERROR records actually committed.
- errors_overflow is TRUE if diagnostics were dropped by the 32-error cap or output capacity.
- truncations is the number of TRUNCATED records actually committed.
- records_emitted includes RUN, all committed inventory and diagnostic records, terminal TRUNCATED if present, and SUMMARY exactly once.
- characters_emitted is the serialized escaped payload total in UTF-16 code units, including prefixes/separators and excluding LF terminators, as already resolved in the schema. Logical length is separately enforced but is not the SUMMARY character counter.
- Any discrepancy between buffered, attempted, and committed records must never be counted as emitted.

### G032-07 — Partial writes and writer failure

A record must be treated as committed only after the writer confirms the complete serialized record and line terminator handling required by the implementation. A partial byte/character write cannot be counted as a committed record.

**Required refinement:** on writer failure, stop ordinary serialization immediately. Do not continue as though reserved capacity guarantees recovery from a failed sink. A terminal attempt is permitted only if the writer abstraction explicitly reports that the failure was transient and a fresh, independently verified sink remains available; absent that separately specified mechanism, mark FAILED and do not claim a valid final SUMMARY. The parser's missing/non-final SUMMARY rule remains authoritative.

## 3. G0.3.1 disposition

G0.3.1 is a useful design proposal but is not yet ready for adoption unchanged. The following amendments are required before G0 can approve it:

1. Replace first-32 retention with deterministic bounded top-32 diagnostic selection.
2. Distinguish diagnostic-cap overflow from output-cap diagnostic omission.
3. Clarify independent logical/escaped reserve accounting.
4. Define a single deterministic primary-reason policy for the one terminal TRUNCATED record.
5. Specify a two-phase bounded collection/sort/serialization plan consistent with schema ordering.
6. Define SUMMARY counters as committed-stream counters.
7. Treat writer failure as FAILED unless a separately reviewed recovery sink is specified.
