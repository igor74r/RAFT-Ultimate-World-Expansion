# v0.1.2 Diagnostic Boundedness Audit

## Scope

Static review of the checked-in RML source at `03 — RML Project/RaftUltimateWorldExpansion/RaftUltimateWorldExpansion/RaftUltimateWorldExpansion.cs`. No execution or runtime performance measurement was performed.

## Summary

v0.1.2 limits many emitted records, but it is not strictly resource-bounded. Several reflection and Unity APIs materialize complete arrays before output caps are applied. There is also no shared global output budget.

This does not prove a runtime performance problem. It means the source does not establish a hard upper bound on allocation, reflection work, or total output.

## Findings

| ID | Operation | Source behavior | Limitation |
|---|---|---|---|
| B01 | `Resources.FindObjectsOfTypeAll(managerType)` | Creates an array of all matching Unity objects | Scene filtering occurs after full array allocation |
| B02 | `AppDomain.CurrentDomain.GetAssemblies()` | Creates the full loaded-assembly array | No maximum assembly inspection budget |
| B03 | `type.GetFields(...)` | Gets all fields, then applies the 24-field output cap | Cap does not cap reflection array allocation |
| B04 | `type.GetMethods(...)` and `GetParameters()` | Gets methods and parameter arrays before output cap | Cap does not cap reflection work/allocation |
| B05 | `Enum.GetValues(type)` | Gets all enum values before logging | No enum-member cap |
| B06 | Dictionary/list enumeration | Iteration has local item limits | Collection Count or enumerator implementation cost is not proven bounded |
| B07 | Independent log sections | Each section has its own cap | No global record/character budget |
| B08 | Completion latch set before scan | Failure can leave probe marked completed | Partial scan may suppress retry |
| B09 | Runtime value formatting | Strings and primitive/enum values can be logged | Arbitrary runtime values are not minimized |
| B10 | First-match type lookup | Returns first assembly match | Duplicate short names are not detected |

## Interpretation

B01–B05 are hard-bound gaps: output limits do not prevent earlier full-array allocation. B07 is a global-budget gap. B08 is a completion-state correctness gap. B09 is a data-minimization gap. B10 is a type-identity correctness gap.

These are source-level findings, not proof that a specific runtime failure or performance regression occurred.

## Required v0.1.3 changes

1. Do not use Unity object discovery in the metadata-only scan.
2. Report the loaded-assembly count and cap subsequent inspection. If the runtime API first materializes an array, document that allocation cannot be bounded by the caller.
3. Cap member formatting/output, while documenting that reflection APIs returning arrays allocate before the cap.
4. Add a shared global record and character budget, plus per-type member, parameter, enum and duplicate-candidate limits.
5. Do not claim strict allocation bounds unless the underlying API supports incremental enumeration.
6. Emit type/member metadata only. Do not dump arbitrary runtime field values, strings, collection contents, or player/world data.
7. Report all duplicate type candidates; never choose the first short-name match.
8. Use explicit states NOT_STARTED, RUNNING, COMPLETE, PARTIAL and FAILED. Set terminal state only after the summary is emitted.
9. Isolate enumerator-disposal and logging failures.
10. Add bounded truncation summaries and deterministic ordering.

## Regression tests

| ID | Scenario | Expected result |
|---|---|---|
| B-T01 | Large assembly set | Inspection cap respected; truncation disclosed |
| B-T02 | Type with many members | Output cap respected; array-allocation limitation documented |
| B-T03 | Large enum | Enum output capped |
| B-T04 | Many target types at local caps | Shared global output budget respected |
| B-T05 | Duplicate type names | Candidates reported; no first-match selection |
| B-T06 | Failure mid-scan | PARTIAL/FAILED, never false COMPLETE |
| B-T07 | Arbitrary instance field values | Values are not emitted |
| B-T08 | Enumerator disposal throws | Cleanup failure isolated |
| B-T09 | Logging fails at budget boundary | No unbounded retry |
| B-T10 | Repeated scan | Stable ordering and no stale completion latch |

## Decision

Keep v0.1.2 source and historical release records unchanged. Incorporate these findings into v0.1.3 before source implementation. This audit does not authorize local build, game launch, or world mutation.
